# macOS Desktop Integration Implementation Plan

**Goal:** Ship a separate arm64 macOS prerelease backed by the installed Xiaomi MiMo Desktop, preserving Windows and all user data.

**Architecture:** Keep the existing loopback DesktopClient and durable task/setup journals. Resolve platform paths explicitly; use a product-owned Swift Accessibility helper on macOS and retain the C# UI Automation helper on Windows. Create sessions only through verified MiMo UI, then verify unique markers, model and completed turns over the local Desktop API. No vendor sources, databases, credentials or runtime assets are distributed.

**Tech Stack:** Electron 45, Node 22+, Swift/AppKit/ApplicationServices, electron-builder DMG.

Base main: b6a90bc001f788bc0036382db35734253039ff04.

## Evidence and decisions
- Local Mac: arm64, macOS 27.0.1. MiMo 26.1014.140704 installed in /Applications; signed-in state confirmed in its account menu.
- Actual descriptor: ~/Library/Application Support/Xiaomi MiMo/desktop-api.json. GET /v1/health returns api=1 and engine=ready; session listing returns IDs and directories.
- Choose native Accessibility + existing loopback API. A UI-only port would lose safe completion/recovery checks; a model API/CLI replacement is prohibited by the product requirements.
- Do not change the white UI, anime assets, defaults, storage schema or automatically bind existing sessions.

## Steps
1. Add failing platform tests for descriptor, application discovery/launch and helper paths. Implement explicit darwin/win32 paths and clear unsupported-platform failures; run all tests.
2. Implement Swift bridge with the existing line-delimited protocol. Fail closed on missing Accessibility, ambiguous UI, changed focus, drafts, running tasks, project context and model mismatch. Use unique verified AX controls. Keep account display in memory.
3. Add setup tests for independent second-group/private sessions, failed model verification, ambiguous creation and restart recovery. Retain durable pre-submit journals and never automatically resubmit.
4. Split native build and resources by target OS/architecture, create ICNS from existing brand PNG, add arm64 DMG and platform-specific checksums. Add Windows workflow guards against non-main/prerelease publishing.
5. Run existing checks and real local MiMo tests using dedicated data and harmless initialization/tasks. Verify single Bot, 3 group members, another group, account name/model, restart/recovery and no duplicate submissions. Record sanitized aggregate evidence only.
6. Commit source, build DMG from that exact clean commit, install from DMG and retest launch/integration. Inspect packaged file allowlist and signature state; generate SHA-256.
7. Push branch, open PR without merging, create independent macOS prerelease/tag pinned to built commit and upload DMG/checksum. Verify remote assets and retain stable Windows v0.4.1.
